# Touch Bistro POS

A touch-optimized restaurant POS prototype with an Express REST API, SQLite persistence, Socket.io updates, and a Vite + React terminal UI.

## Architecture

```
client/ (React tablet UI, Vite build → dist/) → Express REST API → SQLite (WAL mode)
         ↕ Socket.io                                    ↕ transactionally updated inventory
```

The browser owns view state; the server remains authoritative for orders, payments, inventory and floor status. Payment completion is a SQLite transaction: it records payment rows, deducts stock, marks the order paid, and moves its table to cleaning.

## Project tree

```
server.js                 Express, REST endpoints, Socket.io, receipt endpoint, serves dist/
db.js                     SQLite schema, migrations-on-start, sample seed data
models.js                 Domain model registry
client/                   Vite + React frontend (src/App.jsx, components, api.js, styles.css)
dist/                     Production build output (generated by `npm run build`)
```

## Run locally

```bash
npm install
npm --prefix client install
cp .env.example .env
npm run build
npm run dev
```

Vite dev server runs on http://localhost:5173 (proxies `/api` and `/socket.io` to the Express server on :3000). For production, Express serves the `dist/` build at http://localhost:3000, so run `npm run build` first. Use `npm start` for a non-reloading production-style launch. Requires Node 18+ for the client build (repo also runs on Node 20; run `npm rebuild better-sqlite3` if you switch Node versions).

## API surface

- `GET/PATCH /api/tables`, `GET /api/menu`
- `POST /api/orders`, `GET /api/orders/:id`, `POST /api/orders/:id/items`, `DELETE /api/orders/:orderId/items/:itemId`
- `GET/POST/PATCH /api/inventory`
- `POST /api/billing/:id/pay`, `GET /api/billing/:id/receipt`

For a deployment, put authentication/roles, a payment-service adapter with idempotency keys, input validation (e.g. Zod), rate limits, backups, HTTPS, and printer integration in front of this starter.
